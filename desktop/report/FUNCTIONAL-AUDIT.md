# Windows feature audit

This review follows the executable entry point through its Qt Quick shell, application windows, Python services and Windows API calls. It covers the original Windows specification and the subsequent design and authentication requests. The evidence column identifies what was exercised. A source implementation using a Windows API still needs a run on Windows to establish platform compatibility.

## Reproduction

From the repository root, use Python 3.12 or 3.13 with the desktop development dependencies. The Windows Actions workflow uses Python 3.13. Set AIRCURSOR_TEST_WEBENGINE=1 on a desktop where Chromium can use its sandbox. Run the following commands.

```powershell
python -m pip install -r desktop/requirements-build.txt
$env:AIRCURSOR_TEST_WEBENGINE = '1'
python -m pytest -q desktop/tests
python desktop/run.py --self-test
python desktop/tools/benchmark.py policy --notification
python desktop/tools/benchmark.py receiver
python desktop/tools/benchmark.py startup
```

For a real package test on a disposable Windows Actions machine, manually dispatch **AirCursor Windows workspace** on the development branch and enable **Approve installing, launching, upgrading and removing fd**. The test checks the package is absent before mutation. Reproduce AI inference by running a compatible local model server, choosing **Air AI → Configure endpoint**, entering its base URL, choosing **Find models**, selecting a model and sending a message. The localhost media, AI and web fixtures never install software onto the user's computer.
